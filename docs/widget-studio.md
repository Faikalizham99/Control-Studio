# Widget Studio

Version **0.2.13 (15)**. The owner authorized committing, pushing main and pushing the new version tag. The owner will monitor the tag-triggered IPA build; no build monitoring or manual dispatch is part of this release task.

The first builder supports saved, named designs with **Small, Medium, Large and Extra Large** canvases. Extra Large has a layout choice: **Portrait on iPhone/iPadOS 27+** (`systemExtraLargePortrait`) and **Landscape on iPad** (`systemExtraLarge`). Apple introduced the portrait family on iOS/iPadOS 27 in [WidgetKit foundations](https://developer.apple.com/videos/play/wwdc2026/277/). Both layouts can be designed in the editor on any supported device; Home Screen availability depends on the OS/device. iPad support is enabled for the host and both extensions, with iPad-specific orientation declarations.

Portrait is a separate persisted family (`extraLargePortrait`); existing `extraLarge` records remain landscape. New Extra Large designs default to Portrait. The editor retains four size choices and shows the layout picker only for Extra Large. Preview proportions are representative: portrait uses a tall phone canvas; landscape keeps its original wide canvas. Native registration adds portrait only inside an iOS 27 availability check, preserving older OS support.

The build is pinned to .NET SDK **10.0.401**, workload **10.0.401.1**, MAUI **10.0.110**, and **Xcode 27.0 / iOS SDK 27.0** on GitHub's **xcode-27** arm64 image. These versions follow the [Microsoft release](https://github.com/dotnet/macios/releases/tag/dotnet-10.0.1xx-xcode27.0-10722). Xcode 27 requires scene lifecycle adoption: the host registers `MauiUISceneDelegate` with the exact `__MAUI_DEFAULT_SCENE_CONFIGURATION__` name and keeps multiple scenes disabled. Existing MAUI Window activation/resume callbacks continue through the scene lifecycle. The spinning gear now observes scene activation/deactivation and checks its own window scene state so backgrounding stops its timer and reactivation restarts it; Reduce Motion remains respected. Source and IPA validation check the required scene manifest. Minimum deployment stays iOS 17.0.

## User flow

Open **Studio → Widgets → Add**. Choose a name and size, then optionally add photos from **Photo Library** or **Files**. Photos are ordered content layers inside a generic widget design, not a separate widget type. A design may have no photos, in which case its chosen background colour is displayed. The background uses the same reusable colour picker as Settings and Clipboard.

Tap a photo in the live canvas or its layer row to select it. The selected photo has an editor-only outline. Sliders control its horizontal/vertical position, width, height, zoom and crop alignment. Full-width/height photos cannot move along the filled axis; reduce that dimension first. Crop movement is enabled only along axes with image overflow; zoom in for more movement. Cropping retains the original photo's aspect ratio and clips it inside the layer's frame. Raise/Lower change the stacking order; Show layer excludes/includes it; Remove asks for confirmation. Up to eight photo layers and fifty saved designs are supported. Layer names are assigned uniquely within the draft. Same-size designs need distinct names so the Home Screen selector is unambiguous.

**Save widget** commits the draft and requests a Home Screen update. Add **Control Studio → Studio Widget** to the Home Screen in the same size. Touch and hold it, choose **Edit Widget**, then select the saved design. This uses Apple's [App Intent configuration and entity-query model](https://developer.apple.com/documentation/widgetkit/making-a-configurable-widget). With no explicit selection, the first saved design matching the installed size is used. Explicitly deleted designs and wrong-size selections show instructions instead of displaying an unrelated design. The original **Control Studio Counter** widget retains its existing kind and Small/Medium support; existing counters and Shortcuts are unchanged.

The library lists saved designs with small thumbnails, Edit and confirmed Delete actions, alongside the existing counter previews. Refresh retries publication, including an empty catalog after deleting the last design. Opening a nonempty library also retries publication. Empty first-run libraries do not silently replace shared data. iOS decides when a requested refresh takes effect.

## Persistence and publication

`WidgetDesign` stores an ID, revision, name, family, background colour, ordered layer records and immutable render key. Each layer retains an ID, kind (`photo` for now), private source key/dimensions, normalized frame, zoom, crop alignment and visibility. The editable structure is retained for future layer kinds; clocks and text layers are not implemented in this version. Positions scale proportionally when changing sizes; photo crops can change because the canvas aspect ratio changes. Preview proportions are representative rather than an exact device-size contract. The Home Screen fills its actual bounds with the saved composite, which can trim edges slightly on differing device proportions.

The private source of truth is `ControlStudio/WidgetDesigns/catalog.json` below app data, plus `photos/` and `renders/`. Source-generated `WidgetJsonContext` avoids reflection during iOS AOT serialization. Catalog schema 1 rejects unknown fields/kinds/families, corrupt data, unsupported future schemas, invalid frames, duplicate IDs, unbounded values and unsafe keys. Failed reads never reset the catalog. Writes are serialized across repository instances in the host, check revisions to reject stale edits/deleted-item resurrection, install immutable files first and atomically replace the catalog last. Cancellation before commit leaves the previous catalog intact.

The host service then installs immutable composites in the configured App Group's `WidgetDesigns/renders/`, followed by an atomic shared `catalog.json` replacement and `WidgetCenter.reloadTimelines` for `ControlStudio.Design`. The shared root follows the counter store's dedicated/provider-group namespace rule. Missing/corrupt sources, unsupported existing shared catalogs and publication errors do not overwrite the previous shared manifest. A failed publication leaves the private save intact, shows a local-save explanation and can be retried with Refresh. Shared recent renders are retained for cached timelines; unreferenced files older than seven days are removed best effort after a successful publication. Cleanup errors do not block the completed commit or refresh request.

Original library/files images are never modified. Imported images are bounded to the existing 10 MB encoded-input limit, orientation-normalized and converted locally into PNGs with a maximum 1,024-pixel edge and 4 MB encoded size. The editor owns new sources until save/cancel. Removing a newly imported layer cleans up its unused draft source; cancel/departure and late picker completions also clean up. Save retains referenced sources and discards unused drafts. Edits/deletions remove old sources only after the catalog commit and only when no other saved design references them. An abrupt process kill can leave an unreferenced draft or temporary file; no automatic source-directory sweep is performed because an active editor may own those files.

Composites use approximately 2× the representative canvas dimensions with a 1,024-pixel longest-edge cap, RGBA-compatible standard-range output and a 4 MB encoded limit. Library thumbnails have a maximum 256-pixel edge, preventing fifty full-size textures from loading in the scrolling library. The native widget reads one bounded composite rather than decoding every source photo. Full-colour image rendering is requested where supported using [Apple's image rendering modifier](https://developer.apple.com/documentation/swiftui/image/widgetaccentedrenderingmode%28_%3A%29). Photos with transparency composite over lower layers/background. Selection outlines are never included in the composite.

The app requires no account or network requests and adds no third-party dependencies. Development tooling downloads the pinned SDK/workload. Source images stay private; the composite and design metadata are shared with the extension. Logs contain operation/error types rather than user names, images or file paths. The privacy manifests declare container-file metadata access using [C617.1](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype) for bounded reads and cache age checks. No new App Group, entitlement or photo permission is introduced. Widget configuration metadata and iPhone/iPad family declarations are required by native build/IPA validation. Workflow triggers and app/extension version numbers are unchanged.

## Lifecycle, accessibility and review

Draft edits stay local until Save. Busy operations and the native colour picker disable editing/navigation with the existing readable shared action surfaces. Rapid taps cannot launch duplicate imports/saves. Leaving during an import discards the late result. Save finishes its commit before cleaning up; a background or tab change does not delete committed sources. A save completed while inactive closes the editor when it becomes active again; failed navigation still allows Back without saving again. Window subscriptions detach on disappearance. Live crop adjustments reuse image views rather than loading new textures every slider event. UIKit source validation happens before drawing callbacks, and native autorelease pools do not span asynchronous continuations.

The editor uses labelled controls, scalable text, a layer list as an alternative to tapping the canvas, value captions for geometry, and explicit action descriptions. Disabled movement/ordering states keep their text readable. Layout does not require a gesture-only crop workflow or a motion animation. The native widget exposes the design's name for accessibility and shows readable setup/error instructions when unavailable. Real layout, contrast over arbitrary photos, focus order and assistive interaction still require device checks.
