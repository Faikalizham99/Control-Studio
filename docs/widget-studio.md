## Confirmed gallery startup crash and pending correction

The owner's `ControlStudioWidgets-2026-10-23-120527.ips` identifies 0.2.18 (20), iOS 27.0, and an `EXC_BREAKPOINT` / `SIGTRAP` on the main thread about 0.09 seconds after launch. The stack contains Swift `_assertionFailure`, WidgetKit and `StudioSlotConfiguration.make(slot:) + 680` while SwiftUI reads widget bundle preferences. The executable UUID matches the supplied signed IPA. Read-only Mach-O call-site analysis resolves the instruction immediately before that return address to WidgetKit's `configurationDisplayName(LocalizedStringKey)` call, following integer interpolation into `"Studio \(slot)"`. This provides a concrete code-level startup failure, rather than evidence of a photo read or timeline failure. Counter and the slots share the extension, so the registration crash affects all of them.

The signed 0.2.18 extension contains the new slot types and no retired test-widget type or label; its inspected executable code sections match the original unsigned IPA. Its App ID/profile mismatches remain separate findings and were also present in the older supplied 0.2.16 package. They do not account for this demonstrated assertion without additional evidence. Seeing retired gallery entries before reinstall was consistent with stale gallery information; after reinstall the owner confirmed opening the host app once and finding no gallery entries.

The 0.2.19 fix gives each concrete slot widget a literal gallery name (`"Studio 1"` through `"Studio 10"`) and gives the shared configuration a literal, unnumbered description. Widget kinds, slot numbers, families, providers, storage and Counter implementation remain unchanged. Review checked that each literal name matches its provider number and that both bundle groups still register every slot once. Dynamic text in widget content and accessibility labels remains supported.

`scripts/check_widget_metadata.py` now rejects dynamic/interpolated names and descriptions in native widget sources. It runs in source validation and the packaging suite, both already used by branch/PR tests and tag builds. The regression check failed on both original metadata calls before the fix and passes afterward; tests also cover wrapped/concatenated arguments and permit dynamic widget content. This is a narrow source policy, not a Swift compiler or a runtime simulator test. **29 packaging/policy tests**, source/project checks, workflow lint and whitespace checks passed on Windows for this correction. Corrected Swift/Xcode compilation, gallery registration and timeline delivery on iPhone remain unverified. Device checks must confirm Counter Small/Medium plus Studio 1–10, independent Small 1/2 assignments, empty-slot guidance and supported sizes after installation/relaunch. IPA generation remains exclusive to a new version-tag push; no manual dispatch or build monitoring is part of this release task.

## App and Home Screen flow

1. Open Studio → My Widgets → +. Name the design, choose a size and optionally add photo layers. Save widget. The UI reorganization is described in [Studio widget library interface](widget-studio-ui.md).
2. Open Widget slots. Choose Small, Medium, Large, Extra Large Portrait or Extra Large Landscape. Each size has slots 1–10.
3. Tap Assign on a slot, then choose a saved design of that size. The slot displays its name and preview. Change replaces the assignment; Clear asks for confirmation and keeps the saved design and original photos.
4. Add Control Studio → Studio 1–10 on the Home Screen, choosing the matching size/layout. For example, Studio 2 in Small displays Small 2; Studio 2 in Medium displays Medium 2. Those assignments are independent.
5. Remove old custom Home Screen widgets and add the new numbered slots once. Saved designs are retained, with no automatic assignments. The existing Control Studio Counter is kept separately.

Multiple slots may use the same design. Copies of the same slot and size display the same design. Ten different Small designs can be displayed using Small 1–10. Each of the five supported size/layout families has ten addresses (50 assignments total), exposed by ten widget kinds supporting all available families. A slot never substitutes a different photo when empty or unavailable.

Assign/Change choices are filtered by size and use stable IDs. The native choice sheet prefixes names with a number so a design named Cancel cannot collide with cancellation. Repository validation rechecks the ID/size at commit time. Renaming/reordering does not change an assignment. Editing a design updates all slots using it. Changing its size clears its old assignments; changing back does not resurrect them. Deleting a design clears its assignments atomically. Home Screen updates are requests, scheduled by iOS; a failed publication keeps the private assignment and offers Refresh.

The size control stays above the scrolling slot list. Card content has a right gutter for the scroll indicator. Assignment changes update existing cards in place and reuse unchanged image paths, avoiding a full scrolling-list rebuild. Cards use existing Light/Dark glass surfaces, accent/contrast-aware primary actions, readable secondary actions and 44+ point targets. Preview/name labels identify the slot for accessibility, and Assign/Clear success is announced with VoiceOver. Busy actions are guarded. Window activation reloads current assignments; appearance epochs prevent stale asynchronous results from repainting another page lifetime. Picker/confirmation results are checked for foreground state before changing an assignment.

## Sizes and layered editor

Small, Medium, Large and Extra Large canvases are retained. Extra Large has Portrait on iPhone/iPadOS 27+ and Landscape on iPad. The editor can prepare every size/layout; actual Home Screen availability depends on device/OS. iPhone/iPad device-family declarations, the iOS 17 minimum and Xcode 27 toolchain are unchanged.

Photo layers are optional content within a generic design, not a separate widget type. Designs may contain only a background colour. Up to eight layers and fifty saved designs are supported. Photo Library/Files imports retain original source images; imported copies are orientation-normalized, bounded to a 1,024-pixel edge / 4 MB PNG, and rendered locally. Source input remains bounded to 10 MB.

The editor retains positioning, normalized frame sizing, aspect-preserving cover crop, zoom, layer visibility and stacking. Full-size layers cannot move along a filled axis; reduce their dimensions first. Crop alignment moves along image-overflow axes. Changing design size keeps normalized layer geometry. Clocks and text layers remain future work. Thumbnails and canvas proportions are previews; WidgetKit controls device dimensions and may trim an edge when filling its bounds. Shared Settings/Clipboard colour controls and accent behavior remain in use.

## Persistence, migration and publication

The private WidgetDesigns/catalog.json is the source of truth. Private library schema 2 contains designs and slots in one document. Schema-1 libraries are validated and mapped to an empty slot list in memory without rewriting or losing IDs, revisions, names, layers, photos or renders. The first successful save/delete/assignment atomically upgrades the document. A migration test preserves a real source-photo reference, rendered PNG and thumbnail. Older apps do not understand private schema 2; downgrading is not supported.

A shared directory semaphore coordinates repository instances. Assignment, replacement, clearing, resize and deletion validate the complete resulting library and atomically replace one file, avoiding separate private design/assignment commits. Canceled operations, invalid choices, stale editors and unsupported/corrupt libraries are rejected without resetting existing data. JSON serialization is source-generated and tested with reflection disabled.

The shared App Group keeps schema-1 catalog.json for lightweight design summaries and adds bounded schema-1 slots.json (16,384 bytes, at most 50 unique size/number/ID records). Shared publication validates existing manifests, installs immutable composite PNGs first, writes the design catalog, then atomically installs the slot manifest. A native reader always validates the referenced design ID and family, so an intermediate/missing/deleted reference yields assignment guidance rather than another image. The two shared manifests are individually atomic, not one cross-file transaction. Publication failure is reported and can be retried; existing assignments may remain on the Home Screen until iOS refreshes.

Shared PNGs remain bounded to 4 MB and 1,024 pixels per edge. Recent obsolete composites are retained for seven days for cached timelines. The existing private draft/source ownership, stale-revision checks and source cleanup are preserved. A slot assignment does not duplicate or delete source photos. Opening an owned saved library retries publication, including an empty library after deleting the last design. Fresh installations do not automatically replace shared catalogs on an empty first visit.

Assign/Clear reloads the affected numbered kind across families; design save/delete and Refresh reload all ten numbered kinds. The Counter has its own unchanged kind and reload path. Widgets use StaticConfiguration / TimelineProvider and the working UIImage → SwiftUI photo view; no custom widget App Intent or entity query is registered. Gallery registration uses two small WidgetBundle groups, alongside Counter, with stable kinds ControlStudio.Slot.1 through .10.

Gallery snapshots use lightweight explanatory text without reading/decoding photos, reducing the cost of presenting ten entries. The app shows assigned image previews; Home Screen timelines load the actual assigned composite. Empty placeholders perform no storage I/O.
