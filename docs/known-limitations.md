# Known limitations

- Clipboard contains Text, Photo and Link only. Changes to photo import/copy/share, direct icon controls, expandable previews and coloured headers/shared picker require the relevant release's phone checks. Photos are private normalized copies, not original library assets; the share sheet can save a separate copy to Photos. Private clipboard mutations upgrade to schema 4 for optional header colours; the known retired record type is deleted when upgrading versions 1/2 at the owner's request. Previous releases cannot open schema 4. See [Clipboard](clipboard.md).

- iOS compilation requires macOS, Xcode and the pinned .NET workload. This Windows session cannot execute WidgetKit, App Intents, `codesign`, device registration or an iOS simulator. Source/configuration checks do not replace compilation.
- No CI run or IPA is represented as successful until there is an actual workflow log/report. The owner previously confirmed counter/Shortcuts, static Studio slots and the transparent background correction; those confirmations do not validate every subsequent change or OS update. New device tests remain **NOT VERIFIED** until confirmed.
- The unsigned CI path has passed with a real IPA. Expected MT7139 warns that requested App Group entitlements have no provisioning profile during unsigned compilation. Profiles and final signatures are validated separately in signed mode; that path is implemented but has not run with real credentials.
- The target is an iPhone 14 Pro Max on iOS 27. Current pins are .NET 10.0.401, workload 10.0.401.1, MAUI 10.0.110 and Xcode/iPhoneOS SDK 27.0; deployment minimum is iOS 17. Windows managed compilation does not establish native/device compatibility.
- Hosted runner images change even with `xcode-27`; SDK/workload/Xcode versions are pinned and checked, while the complete runner image cannot be frozen with a standard hosted label. Removed Xcode versions produce an explicit failure.
- App Groups require matching authorization for all three targets. Historical supplied FlareStore artifacts had provisioning/application-identifier inconsistencies; that inspection is not a verdict on the current installed artifact. Provider group access may also be granted to other apps; an app-specific subfolder is not an isolation boundary. No capability is fabricated or silently stripped. Private host fallback does not make shared widgets or Shortcuts work.
- FlareStore installation has worked for the owner, but its preservation/signing of future WidgetKit **and ExtensionKit** products still requires final-artifact/device verification. Its public signing API alone does not prove that flow. Re-signing invalidates the original signature report; validate the final artifact again where possible.
- WidgetKit schedules refreshes. Reload requests and the 15-minute timeline policy do not guarantee immediate or periodic updates. Counter Last Updated refers to data mutation, not rendering time. Clock/Date use native live Text; iOS may reduce seconds while dimmed. Battery samples at timeline generation rather than continuously or at every percentage change. No arbitrary background tasks or unrestricted app launching is promised.
- App Intent build-time metadata presence does not prove Shortcuts discoverability or execution. System indexing, extension registration, signing, device lock state and OS behavior require device testing.
- SQLite operations may fail while storage is unavailable/locked or another writer exceeds the busy timeout. The app reports errors; it does not reset a corrupt database or retry committed mutations automatically. A response allocation failure after commit cannot undo that commit.
- The counter is limited to 2147483647. Home now supports a confirmed reset to zero; uninstall/re-signing can change container availability. There is no automatic migration/merge between private fallback and shared storage.
- The UI supports Home, Studio, Clipboard/widget editors, Settings, light/dark appearance and semantic accessibility labels. Large-text/VoiceOver usability and regression behavior require physical checks. Clipboard pinning/arrangement and a 30-layer Photo/Clock/Date/Text/Battery widget builder are implemented. Lock Screen widgets and interactive widget buttons remain deferred. Ten static Studio kinds have independent Small/Medium/Large/iPhone XL assignments; XL needs iOS 27 and live scenes need iOS 18. Gallery/slot images are saved previews. The former App Intent design selector remains intentionally absent.
- Dashboard names, links and copy text are plain text in private SQLite, separate from the provider App Group. They are not encrypted as a password vault. Running Copy writes to the system clipboard. Keep the same identity when updating; uninstalling or changing the signed app identity can lose private data. There is no dashboard export/import UI yet.
- The app makes no mandatory backend/tracking requests. Opening or long-press previewing a Link performs explicit user-initiated network access. GitHub CI and certificate revocation checks by installation tools are outside the application's local storage model.
- True transparent display uses a guarded private iOS 27 descriptor adapter, with fallback when the ABI is incompatible. Retest after OS updates; a clear PNG alone does not guarantee a clear Home Screen background.
- Hidden live layers currently retain photo-group boundaries and can affect blending across those boundaries. Changing that safely requires saved-scene compatibility coverage. Main-thread 30-layer composition and full catalog publication need target-device performance measurements. See the [audit](architecture-audit.md).
- Profile preferences remain separate keys rather than a crash-atomic record. The audit fixes failed-write state/ownership and navigation recovery, but does not introduce a new settings format or a general backup/restore feature.
