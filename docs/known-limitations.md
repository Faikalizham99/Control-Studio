# Known limitations

- The current Clipboard work adds Text, Photo, Link and Snippet sections; it supersedes the older image deferral below. Photo import/copy/share and code preview integration still require phone checks. Beautify supports JavaScript, TypeScript, JSON, HTML, CSS, Markdown, C, C++ and C#; Swift, Python, SQL, Shell and XML have viewing/highlighting only. C-family formatting uses bundled clang-format WebAssembly; its WKWebView initialization/CSP and actual phone formatting remain unverified. Photos are private normalized copies, not original library assets; the share sheet can save a separate copy to Photos. Private clipboard mutations upgrade to schema 2, which previous releases cannot open. See [Clipboard](clipboard.md).

- iOS compilation requires macOS, Xcode and the pinned .NET workload. This Windows session cannot execute WidgetKit, App Intents, `codesign`, device registration or an iOS simulator. Source/configuration checks do not replace compilation.
- No CI run or IPA is represented as successful until there is an actual workflow log/report. All device tests remain **NOT VERIFIED** until the owner confirms them.
- The unsigned CI path has passed with a real IPA. Expected MT7139 warns that requested App Group entitlements have no provisioning profile during unsigned compilation. Profiles and final signatures are validated separately in signed mode; that path is implemented but has not run with real credentials.
- The physical target is an iPhone 14 Pro Max on iOS 27, but the verified toolchain baseline uses iOS 26.5 SDK APIs and deployment minimum 17.0. Running on a newer OS is intended, not device-tested. Upgrading to an iOS 27 SDK requires a separately verified Microsoft/Xcode pairing; preview support is not silently enabled.
- Hosted runner images change even with `macos-26`; SDK/workload/Xcode versions are pinned and checked, while the complete runner image cannot be frozen with a standard hosted label. Removed Xcode versions produce an explicit failure.
- App Groups require matching authorization for all three targets. The owner's supplied FlareStore profile and XML/DER entitlements were inspected, and the current selected provider group was present. The supplied file lacks embedded extension profiles and uses mismatched signed application identifiers; final provisioning/signature validity remains unverified. No capability is fabricated or silently stripped. Private host fallback does not make shared widgets or Shortcuts work.
- FlareStore's preservation/signing of WidgetKit **and ExtensionKit** products with separate profiles is unverified. Its public signing API does not prove that flow. Re-signing invalidates the original signature report; validate the final artifact again where possible.
- WidgetKit schedules refreshes. Reload requests and the 15-minute timeline policy do not guarantee immediate or periodic updates. Last Updated refers to data mutation, not rendering time. No continuously updating clock, arbitrary background tasks or unrestricted app launching is promised.
- App Intent build-time metadata presence does not prove Shortcuts discoverability or execution. System indexing, extension registration, signing, device lock state and OS behavior require device testing.
- SQLite operations may fail while storage is unavailable/locked or another writer exceeds the busy timeout. The app reports errors; it does not reset a corrupt database or retry committed mutations automatically. A response allocation failure after commit cannot undo that commit.
- The counter is limited to 2147483647. It has no reset/delete action in Milestone 0; uninstall/re-signing can change container availability. There is no automatic migration/merge between private fallback and shared storage.
- The UI supports Home, a private Shortcuts dashboard/editor, Settings, light/dark appearance and semantic accessibility labels. New 0.2.0 visual rendering, large-text/VoiceOver usability and regression behavior remain device checks. Dashboard actions support HTTP(S), copy text and the internal counter. Additional schemes, drag-and-drop, images, variable tile sizes, a widget builder, Lock Screen widgets and interactive widget buttons are deferred.
- Dashboard names, links and copy text are plain text in private SQLite, separate from the provider App Group. They are not encrypted as a password vault. Running Copy writes to the system clipboard. Keep the same identity when updating; uninstalling or changing the signed app identity can lose private data. There is no dashboard export/import UI yet.
- The offline app makes no mandatory network requests. GitHub CI and certificate revocation checks by installation tools are outside the application's local storage model.
