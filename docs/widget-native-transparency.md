## Research and scope

The public [ClearAndBlurredWidgets sample](https://github.com/pookjw/ClearAndBlurredWidgets/blob/main/MyWidget/FooObject.mm) intercepts WidgetKit's descriptor callback and sets `backgroundRemovable`, `transparent` and `preferredBackgroundStyle` (1 for clear) on mutable widget descriptors. These are private runtime APIs, not the public SwiftUI `containerBackground` API. The sample's [iOS 27 safety proposal](https://github.com/pookjw/ClearAndBlurredWidgets/pull/6) reports a physical-device crash while reconstructing the private Swift result and proposes defensive changes. It is not proof that every iOS 27 device supports this technique.

Widgy's [developer announcement](https://www.reddit.com/r/widgy/comments/1w5rb1m/announcing_widgy_v27_public_beta_next_week/) and WidgetLoft's [creator guide](https://mucahitk.com/blog/transparent-widget-iphone) describe screenshot-free transparent widgets. Their exact proprietary implementations were not inspected. The adapter follows the independently published descriptor mechanism; it does not claim access to either app's source.

The adapter runs only on iOS major version 27 and only changes the ten exact `ControlStudio.Slot.1` through `ControlStudio.Slot.10` kinds. Counter descriptors, controls, Live Activities and unrelated kinds retain their encoded values. All four Studio sizes use the same slot descriptors. Descriptor policy is per kind, so all ten slots request clear containers; solid designs retain their background inside their saved PNG. Empty/error views explicitly paint their own readable system background. No wallpaper screenshot, new setting, blurred-background option or data migration is introduced. Existing alpha exports, slot assignments and persistence remain unchanged.

## Defensive implementation

`native/WidgetRuntime/CSWidgetBackgroundAdapter.m` is compiled only into the widget extension, with ARC and a widget-only Swift bridging header. WidgetBundle initialization attempts installation and queues one main-thread retry. Unsupported OS versions, missing classes, unexpected method signatures and unavailable methods leave normal rendering in use.

The callback archives the original secure-coded result and decodes its original class. A public `NSKeyedUnarchiver` delegate substitutes independent mutable copies of matching descriptors. This preserves fields handled by the original class's coder, including future encoded metadata, instead of manually rebuilding a private Swift result with a selected set of fields. Each request has its own decoder/delegate state. The adapter checks descriptor method signatures before dispatch, rejects mutable copies that return the original object, bounds accepted archives to 8 MiB, and returns the original result if any target cannot be safely patched. It does not read or rewrite design/photo data. The 0.2.24 diagnostics follow-up below queues small diagnostic snapshots to shared storage separately from the descriptor callback.

This guards detected incompatibilities; it cannot guarantee that undocumented framework behavior remains compatible. The delegate substitution approach itself still requires native verification. Future OS major versions intentionally use normal rendering until reviewed. iOS may retain system chrome or alter rendering in Clear/Tinted styles even when the descriptor request succeeds; a fully invisible outline is not established by the sample or local checks.

## Diagnostic report follow-up (0.2.24)

This follow-up records evidence without changing installation timing, private API choices, descriptor policy, saved images or slot assignments. Open **Settings → Widget diagnostics**. View a Studio slot in the Home Screen widget picker, return to the app, and choose **Refresh report**, then **Copy report**. The page also refreshes on return from the Home Screen. No app uninstall or design deletion is needed. Refresh reads captured evidence; it does not force iOS to refetch descriptors. If the adapter installed but no callback was captured, that is reported explicitly. The report also distinguishes a received callback without a saved outcome, a returned changed result, and specific installation/rewrite fallback codes. Successful rewriting is always described as a request, never proof of transparent display.

The widget extension captures WidgetBundle entry, installation outcome, fetch/callback stages, changed slot kinds/counts and reasons such as missing classes, incompatible method signatures, unavailable setters, invalid mutable copies, secure decode failure and no matching slots. Known error domains and numeric error codes can be included; localized errors, exception reasons, private archives, design names, image paths, photos and clipboard contents are not recorded. Each process has a UUID session with its own version/build, OS and UTC timestamps. Current version **and build number** are required before a report is treated as current. If only older data exists, it is labeled as older/different build and cannot imply success for the installed app.

The extension writes only to `Library/Application Support/ControlStudio/WidgetBackgroundDiagnostics` inside its configured App Group. An in-memory lock bounds recent history to 64 events and latest stage summaries to 12. A serial queue coalesces writes off the descriptor callback, atomically replaces the per-session JSON, applies protection until first unlock, and prunes only UUID-named JSON files to 16 recent owned sessions. Simultaneously active processes can temporarily exceed that retention limit. Each accepted snapshot is at most 64 KiB. Unrelated files are not pruned. Diagnostic I/O failures are isolated from descriptor delivery; unavailable group access or extension termination can prevent evidence from being written. Missing evidence must not be treated as proof the hook did not execute.

The host reads at most 32 candidate snapshots, enforces the size/schema/session checks, reports unreadable/unsupported files and displays up to three current-build sessions (or one explicitly stale session). Copy writes exactly the displayed report to the system clipboard only after a tap. Nothing is uploaded. Shared readable disabled actions preserve contrast in Light/Dark and follow the app accent when enabled. Copy success/failure is announced for accessibility. Reads/copies cannot overlap; page departure or backgrounding prevents stale completions from changing the UI, and return to the foreground refreshes the report. A failed refresh clears the old report rather than leaving stale evidence copyable.

Windows verification for this follow-up: **162 app tests**, **32 packaging tests**, managed iOS C# compilation, source/generated-project checks and whitespace checks pass. Fourteen new managed tests cover report filtering, stale builds, malformed/oversized data, retained stage summaries, truthful status messages, explicit copy, failure handling and page lifecycle. Five native recorder tests were added for atomic snapshots, bounded histories/retention, concurrency, failed storage and text bounds; those and the existing native adapter tests still require macOS. ## Signed background-style signature correction (0.2.25)

The owner's **0.2.24 (26)** report from iOS **27.0 (24A437)** confirms that the adapter installed, the descriptor fetch ran and its callback arrived. Ten slot checks then recorded `setPreferredBackgroundStyle: expected=Q actual=q`, followed by `setter-unavailable-or-incompatible:setPreferredBackgroundStyle:`. This establishes why this descriptor rewrite was discarded: our guard and typed setter declaration assumed unsigned `NSUInteger` (`Q` on this 64-bit target), while the device reports signed `NSInteger` (`q`). It does not establish what the compositor will display after a successful rewrite.

The owner authorized correcting that mismatch. The private protocol declaration and exact argument-type check now both use `NSInteger`; the clear value remains 1. This is a typed-call correction, not a bypass of signature validation. Unexpected unsigned/object setters, absent APIs and all other existing failures still return the original result. The exact ten-kind allowlist, copy-before-edit behavior, archive/decode checks and diagnostics remain in use. Counter, controls, Live Activities, Light/Dark appearance, alpha rendering, saved designs and slot assignments are unaffected by this focused change. There are no new gestures, visual controls, permissions, data formats, retention rules or workflow triggers.

The positive native fixture previously used `UInt`, repeating the incorrect production assumption. It now uses signed Swift `Int`, including secure coding and copying, so the existing ten-slot/Counter/metadata and concurrency tests exercise the reported signature. Two additional native tests assert that the signed fixture actually exposes Objective-C encoding `q` and can be rewritten, and that a separate `Q` fixture is rejected without modifying the original. The object-typed wrong-ABI test and missing-setter/invalid-copy/decode-failure tests remain.

Local Windows checks for this correction: 32 packaging tests, source/generated-project checks and whitespace checks pass. Native tests and Xcode compilation cannot run here and remain pending on macOS. Returning changed descriptors still is not an iOS delivery acknowledgement. The owner subsequently authorized committing, pushing main and pushing the new version tag. ## Diagnostics removal and cleanup (unreleased)

After testing 0.2.25, the owner reported that transparency works and authorized removing the temporary diagnostics feature and cleaning up its saved reports. Settings no longer offers Widget diagnostics. The report page, reader, iOS report service, Objective-C recorder/header, recording hooks and diagnostic-only counters/reasons/logging are removed. The generated project no longer compiles the recorder. Fourteen managed report/page tests and five native recorder tests are removed with those features. Historical release notes and the signed-signature evidence remain as documentation.

The working adapter still uses `NSInteger` for the background-style setter and exact ABI guard, preserves its ten-slot allowlist, original-result fallback, independent mutable copies, complete secure-coded descriptor result, exception guards, atomic original implementation and single main-queue installation retry. Its 11 native tests, including actual `q` acceptance, `Q` rejection, all ten slots, Counter/other metadata preservation and concurrent requests, remain. No report generation or storage access occurs in the widget adapter. Removing logging does not change rendering, slot assignments, saved designs, Counter data or the shared colour/theme behavior.

The host schedules a small one-time migration off the UI thread when its window activates. It resolves the configured App Group and deletes only top-level `UUID.json` files from `Library/Application Support/ControlStudio/WidgetBackgroundDiagnostics`, removing that directory only if empty. It does not recurse, traverse linked directories, clear the clipboard, or remove unknown files, nested folders, designs, images or counter data. Completion is saved in private preferences per App Group. If group access, protection, permissions or preferences prevent completion, launch continues and a later activation retries. Overlapping activations cannot run two cleanups concurrently. The completion marker makes successful cleanup durable across app restarts; the retired folder is not recreated.

Migration coverage checks owned-file deletion, preservation of other data and unknown content, unavailable-group retries, persistent/scoped completion, missing directories, blocked paths and preferences failures.
