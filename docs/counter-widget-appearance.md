# Counter widget appearance

The owner authorized implementation of Settings theme/accent sharing for Small/Medium Counter widgets and their in-app previews, then explicitly authorized committing and pushing main. The subsequent **0.2.21 (23)** release/tag authorization includes this enhancement. Its earlier branch push did not generate an IPA.

Settings retains the existing System/Light/Dark choice and exact six-digit accent. The app publishes only those two committed values and schema version 1 into `counter-appearance.json` in the existing app-specific App Group directory. No profile information, Counter database values, custom designs or slot assignments are copied or changed. Publication runs on app attachment, saved theme/accent changes and window activation. Local slider previews update the app immediately; they publish when committed rather than for every drag movement. A failed publication is logged without sensitive values and retried on activation; local Settings remain usable.

The Swift bridge validates the values and atomically replaces the small appearance file. An identical saved appearance leaves the file alone and requests no widget reload. Changed appearance requests a reload of `ControlStudioCounter` only. Counter increment/reset and custom slot registration/refresh behavior remain unchanged. The host and widget use the same native path resolver, including the provider-group namespace. No new entitlement or permission is required.

Counter placeholder, gallery snapshot, normal timeline and error presentation carry the appearance. A missing, unreadable, oversized, malformed or unsupported file falls back to System/blue; appearance loading cannot fail an otherwise valid Counter timeline. Reads are bounded to 4 KiB plus an overflow byte. System resolves from the widget's own SwiftUI color-scheme environment at rendering time, allowing system appearance changes without writing a forced Light/Dark value. Explicit Light/Dark uses fixed readable foreground/background colors. Both icons use the exact selected accent over a small contrasting black/white rounded well; their contrast is at least 4.5:1, including black/white/neon accents. Timestamp and secondary text remain neutral and readable. The in-app previews use the same palette and live accent resources.

The widget continues to use [SwiftUI's color-scheme environment](https://developer.apple.com/documentation/swiftui/environmentvalues/colorscheme) and [WidgetKit container backgrounds](https://developer.apple.com/documentation/widgetkit/displaying-the-right-widget-background). Home Screen tint/clear rendering can apply a system treatment, so the full-colour preview does not represent every system rendering mode. A reload request is not acknowledgement that iOS has rendered or delivered an update.

The new app tests cover startup/relaunch settings, every theme, normalized accents, local slider previews versus commits, activation/retry failures, and actual Small/Medium preview resources/contrast across Light/Dark and extreme accents. They are included by the existing Swift package but cannot run on Windows. The new Swift source is included in both the bridge build and WidgetKit Xcode source phase. Swift compilation/linking, the new C bridge ABI, native storage tests and UIKit/WidgetKit rendering require macOS/Xcode.
