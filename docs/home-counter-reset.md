# Home counter reset

The owner authorized adding Reset to Home, explicitly choosing red for the button, then authorized committing, pushing main and pushing the new version tag. This ships alongside the Studio UI changes in **0.2.20 (22)**. The owner will monitor the tag-triggered IPA build.

Home labels its existing mutation **Increment (+1)** and places a **Reset counter** action below it. Reset uses a filled red surface and white text in Light/Dark, independent of the app accent. Its disabled state retains a readable red-tinted surface, caption and outline rather than an opacity fade. The action remains visible at zero, with an accessibility hint explaining why it is disabled. The shared secondary-action component's default palette is unchanged for other consumers.

Reset is enabled only after a nonzero counter has been loaded. It asks “Reset counter to 0?” with Reset/Cancel actions. Cancel performs no mutation. Confirmation is checked against the current page lifetime and active window; leaving Home or backgrounding during the confirmation prevents the reset. Reads, increments and resets serialize at the page boundary, with buttons/Refresh disabled while busy. Repeated taps do not open more dialogs or queue duplicate resets. Appearance/window activation reloads the current stored value, and reads from earlier appearances cannot repaint the current screen.

`ICounterRepository.ResetAsync` calls `INativeCounterBridge.Reset`, implemented by `AppleCounterBridge` through the new `cs_counter_reset` entry point. Swift's CounterStore performs the reset in its existing `BEGIN IMMEDIATE` transaction and schema-1 database, validating the existing record before writing zero and the current timestamp. It does not replace the database or reset unsupported/corrupt data. Concurrent Shortcut/widget updates use the same SQLite transaction ordering: an increment after the reset starts from one. Increments that commit before the reset are intentionally cleared by it.

The bridge requests a reload of the existing Counter widget kind after a shared reset. Small/Medium Counter widgets therefore receive the same update request. Static design slots, designs, photo files and Clipboard data are not reset. When App Group access is unavailable, the existing host fallback resets only its private local counter; the UI explicitly reports local storage and does not claim a shared widget refresh. Existing shared values are not merged with private fallback values.

Cancellation is honored before the native operation starts. Once a native mutation has started/committed, its returned snapshot is not hidden by a subsequent cancellation. Failed/uncertain operations clear the displayed snapshot and require a successful Refresh before Reset is offered again. Successful commits update the visible value, timestamp and status. Accessibility announcements are best effort and cannot turn a committed mutation into a reported storage failure; the same separation is used by the new widget-page feedback.

## Verification

**280 automated tests passed:** 65 Core, 54 infrastructure, 132 app and 29 packaging/policy. Core/infrastructure ran with reflection-based JSON serialization disabled. Managed MAUI iOS C# compilation, source/project checks, workflow lint and whitespace checks passed. App tests cover confirmation/cancellation, zero-state disabling, duplicate requests, leaving/backgrounding, recovery after failure, local fallback wording, and red/disabled contrast across live theme/accent changes. Enabled/disabled captions pass 4.5:1 contrast; disabled outlines pass 3:1. Bridge tests verify reset routing, timestamp/refresh response, pre-start cancellation and committed-result handling.

Three new Swift storage tests cover persistence/next increment, maximum/local reset, and concurrent resets/increments. Existing unsupported-schema and invalid-timestamp tests also reject reset without changing invalid data. These tests have **not run on Windows**. Native Swift compilation/linking (including the new C export), SQLite concurrency on Apple platforms, confirmation presentation, VoiceOver, relaunch persistence, widget timeline delivery and Shortcut increment after reset still require macOS CI and an iPhone. A refresh request does not guarantee immediate delivery by iOS.
