# Compact widget tools and blend illustrations — 24 October 2026

The owner authorized replacing the two-row tool grid with one rounded icon toolbar, adding visual examples for all 14 blend modes and adding icons to Normal/Darken/Lighten/Contrast/Effects group tabs, then authorized committing, pushing main and pushing the new v0.2.29 tag for version 0.2.29 (31). The owner will monitor the IPA build. This release also includes the previously committed action-spacing update.

## Behaviour

- Reset, Rotate, Flip, Blend, Opacity and Delete occupy one horizontal glass-style strip. Each native button retains its 48×48-point target. There are no permanent tool captions; VoiceOver names remain, the opacity percentage appears in its open panel and accessibility name, and Delete remains red with confirmation.
- Narrow layouts scroll the strip horizontally instead of wrapping or shrinking buttons. Four-point spacing inside this single grouped bar is intentionally more compact than the eight-point gap between independent action buttons elsewhere. Selection is revealed without animation after opening a panel or a structural size change. Manual scrolling remains available.
- Rotate/Flip/Blend/Opacity use the current accent surface and contrast-aware foreground while their panel is open. Panels remain open during repeated adjustments. Switching tools, tapping the active tool, Done, changing layer, canvas manipulation, backgrounding or leaving the editor clears the appropriate highlight. Closing tools also resets a cancelled press scale.
- All five blend group tabs contain a local vector symbol and the group name. They scroll horizontally, with natural text sizing and a minimum width rather than squeezing five captions into the page. Normal uses overlapping layers; Darken/Lighten use filled/open overlapping circles; Contrast uses a split circle; Effects uses contrasting coloured shapes. Group browsing does not change the layer's blend mode.
- All 14 mode cards contain the name plus a thumbnail of the same cyan/blue and orange/pink shape layers, with light/dark bands showing variation in their overlap. A check and the current accent mark selection. Names can wrap and the cards grow vertically for larger text. The actual widget still previews the chosen mode immediately.

## Rendering, lifecycle and review

`AppleWidgetBlendSamples` creates 176×128 PNG examples from fixed local geometry. It uses the same built-in `CIBlendKernel` mapping as the production compositor and the same sRGB working/output settings; it does not approximate Darker/Lighter Color with component-wise min/max. The shapes blend on transparency before being presented over neutral paper. They are generic examples, not a rendering of the user's current photo/background configuration. No photo paths, files, network requests, photo-library permissions or saved designs are involved.

Generation is asynchronous, serialized and cached in memory for at most 14 mode values, with a reused sample context. This follows Apple's recommendation to [reuse Core Image contexts](https://developer.apple.com/documentation/coreimage/cicontext). Each view owns its own [cancellable stream image source](https://learn.microsoft.com/dotnet/api/microsoft.maui.controls.imagesource.fromstream), returning a fresh read-only stream per load. The cache retains only mode keys, tasks/PNG bytes and native rendering resources, not page/view instances. Hiding a group/panel or leaving the editor clears its image sources. At most the current group's four examples are active; an already-started small shared generation can finish for later reuse. Selection changes reuse the existing source instead of regenerating an example. Before load, or if loading fails, a neutral blend glyph keeps the mode's name usable.

Review found that newly asynchronous samples could share built-in native kernel wrappers with the live compositor. The mapping now retains the bounded set of wrappers for the application lifetime instead of disposing a shared wrapper after each application. Source images, raster buffers and per-render graphs still follow their existing disposal rules. Choice foreground bindings update only when selection changes, avoiding rebinding all 14 labels during a photo gesture. Native image dimensions are fixed, so asynchronous loading does not change card layout.

The existing layer model, persisted blend names, bounds, photo geometry, export dimensions, static slot registrations, App Group data and tag-only IPA policy are unchanged. The change preserves the existing native button IDs, callbacks, busy-state checks, reset behaviour, picker cancellation recovery and save/cancel semantics. No new storage or downloaded visual assets were introduced.
