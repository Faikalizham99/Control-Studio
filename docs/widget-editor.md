# Photo layer editor

The owner authorized the editor redesign from the supplied glass-card reference, including live manipulation and transparent backgrounds, then explicitly authorized committing, pushing main and pushing a new version tag. This ships in **0.2.22 (24)** alongside the shared button-caption alignment fix. The owner will monitor the tag-triggered IPA build. The existing ten static slot registrations, literal gallery metadata, Counter widget and tag-only IPA workflow remain in use.

## Editing

The editor uses a plain Light/Dark page with themed glass cards and the current app accent. Small, Medium, Large and iPhone XL segments change the preview proportions. The representative canvas sizes remain 170×170, 364×170, 364×382 and 364×594, scaled down only when the available width is smaller. WidgetKit controls actual Home Screen dimensions. XL requires iOS 27; retired iPad layouts still open as unsaved iPhone XL copies.

Tap a visible photo to select it. Drag moves its frame; pinch changes both dimensions around the gesture anchor; the four corner targets change width and height independently while holding the opposite corner. Native gestures temporarily suspend the ancestor scroll view, restore its previous state on completion/cancellation/disconnection, and restore the original layer if interrupted. Other editing actions are unavailable during manipulation. Geometry is bounded to the canvas with a minimum normalized width/height of .05. Tests caught and corrected floating-point subtraction at the minimum size that could otherwise reject a valid save.

The toolbar offers Reset, quarter-turn Rotate Left/Right, horizontal/vertical Flip, Opacity and confirmed Delete. Rotation turns the photo inside its cover-cropped frame. Reset centers an aspect-fitted frame within 80% of the canvas and restores rotation, flips, opacity, zoom and crop. It keeps the photo identity, name and visibility. Switching tools closes the previous tool panel. The opacity tool displays its current percentage.

Layer rows retain their thumbnail and native visibility switch across geometry updates. The list shows the topmost layer first. Drag the handle to reorder within this editor; the menu also provides Move forward/backward for accessible reordering, Rename, Size/position/crop and confirmed Delete. The precise panel retains independent dimensions, position, zoom and overflow-axis crop controls. Opening it scrolls it into view and respects Reduce Motion. Photo import still offers Photo Library and Files, enforces the existing eight-layer limit, and owns imported draft assets until saved or explicitly cleaned up.

Save renders and atomically persists the design through the existing repository, republishes assigned static slots, and marks the draft saved before attempting navigation. Cancel/navigation does not rewrite existing designs. Backgrounding cancels an active gesture and closes tool panels. Foreground checks reject late sheet actions; an already committed save can finish navigation after activation. Cleanup retains sources referenced by saved designs. Repeated live edits reuse image views instead of decoding each source for every gesture update.

## Transparency and compatibility

New designs start with no background fill on iOS 26+. Older systems start with a solid background. The reusable Settings/Clipboard colour picker supplies the optional solid colour. Existing designs without the new field keep their solid background. Switching modes retains the last valid solid colour.

The model adds optional `transparentBackground` (legacy default false), `quarterTurns` (0), `flipHorizontal`/`flipVertical` (false) and `opacity` (1). Existing private schema-1/schema-2 libraries and shared schema-1 catalogs still decode without rewriting on read. Reflection-disabled round-trip and repository tests cover the new values, slot retention, publication and rejected-edit preservation. Downgrading is unsupported: previous hosts reject these unknown fields through their strict decoder instead of silently discarding new edits. The Swift summary reads transparency as an optional Boolean for legacy catalogs.

UIKit exports both the full PNG and thumbnail with alpha when the design is transparent; the renderer clears rather than fills the canvas. Crop placement accounts for quarter turns, with matching native and MAUI rotation/flip/opacity transforms. The editor/gallery/slot checkerboard is a separate decorative view and is never part of either exported image. The native slot view uses a clear container for transparent designs and retains a system background for empty/error entries and legacy solid designs. Photos retain the existing full-colour accented rendering mode.

**Actual wallpaper-through transparency has not been verified.** Alpha PNGs and a clear WidgetKit container are implemented; they do not establish how the iOS compositor will display the widget in every Home Screen style. Apple's [widget background documentation](https://developer.apple.com/documentation/widgetkit/displaying-the-right-widget-background) and [Liquid Glass guidance](https://developer.apple.com/documentation/WidgetKit/optimizing-your-widget-for-accented-rendering-mode-and-liquid-glass) describe system control over widget backgrounds. WidgetLoft's [first-party guide](https://mucahitk.com/blog/transparent-widget-iphone) reports transparent widgets on iOS 26+, but does not publish its implementation. This change uses public APIs and does not implement a wallpaper-screenshot workaround or claim equivalence before an iPhone test.

## Review and verification

Local automated checks: 76 Core tests, 57 Infrastructure tests, 148 MAUI control/logic tests and 29 packaging/policy tests (310 total). These include all four preview families, rotation/crop geometry, resize/scale bounds, gesture commit/cancel, topmost/hidden hit testing, source/switch reuse, legacy defaults, new-field serialization, persistence, publication and slot preservation. Managed iOS C# compilation and source/project checks also pass. The Swift compatibility test is added for the macOS suite and cannot run on Windows. Native Xcode linking, UIKit pixel rendering and a rendered device UI review have not run locally.

Device checks still required: match reference spacing in Light/Dark at narrow widths and large text; current accent and contrast; photo import from both sources; tap/drag/pinch/corner interactions and page scrolling; layer drag and menu reorder; selected/hidden/zero-opacity layers; all tools and transform agreement between preview and saved Home Screen image; cancellation during gestures and native pickers; Save/Cancel/relaunch and assigned-slot updates; VoiceOver controls and Reduce Motion; transparent image edges over the actual wallpaper in default, tinted and Clear styles; solid background fallback; and unchanged Counter/Clipboard behavior.
