# Photo layer editor

The owner authorized the editor redesign from the supplied glass-card reference, including live manipulation and transparent backgrounds, then explicitly authorized committing, pushing main and pushing a new version tag. This ships in **0.2.22 (24)** alongside the shared button-caption alignment fix. The owner will monitor the tag-triggered IPA build. The existing ten static slot registrations, literal gallery metadata, Counter widget and tag-only IPA workflow remain in use.

## Off-canvas photo workspace (unreleased, 24 October 2026)

The owner authorized Photoshop-style placement: drag a photo past widget edges, resize the whole photo proportionally, see its outside portion faintly while editing, and save only the widget area. The former normalized position/frame limits and unconditional cover cropping prevented that behavior.

The editor now gives the widget a 32-point workspace margin. The selected photo's outside portion is shown at 22% of its layer opacity behind the actual widget preview. The real preview remains clipped to its own canvas; a checkerboard or solid background masks the ghost inside it. One extra image view reuses the selected layer's source, rather than duplicating every layer or regenerating bitmaps for each gesture. Unselected layers remain visible normally inside the widget. The ghost source is cleared when its layer is removed/hidden, and all sources are cleared when the editor leaves navigation. The outside area, selection outline and handles never enter the export renderer.

Dragging allows negative positions and overflow on all edges. Pinch and corner resizing scale both frame dimensions together; a two-finger pinch also follows centroid translation. Opposite-corner/gesture anchors are retained until workspace limits apply. Frames remain finite: positions range from -4 to +4 widget dimensions, and each dimension ranges from 5% to 400% of the corresponding widget dimension. These are generous workspace limits rather than a requirement to stay inside the widget. Precise position controls support the same range. Small-layer handle hit areas adapt to the frame size so a central drag is not mistaken for corner resizing. Preview-size changes, backgrounding and interrupted gestures cancel the in-progress transform and restore scrolling.

New imports and Reset default to **Show full photo**. This uses aspect-fit geometry, ignores stored internal zoom/crop settings, and keeps the whole source visible inside its frame. Pinch/corners and precise width/height controls scale proportionally in this mode. Quarter-turn rotation swaps physical frame dimensions around its centre when within limits, keeping the full image visible. **Crop to frame** is an explicit alternative that retains the original cover/zoom/crop behavior; its precise width and height controls can change the frame independently. The layer menu and precision panel offer these choices. Toggling modes retains the old crop settings so toggling back can recover them.

**Centre on widget** is available in the layer menu and precision panel. It restores a completely off-screen layer to the widget centre while preserving its current scale, rotation, opacity, flips, image and crop choice. For an older cropped photo, choose **Show full photo** in its layer menu to reveal the original edges without resetting other edits. The original source image is never modified.

The optional layer field `fitPhoto` defaults to false when absent, preserving old crops. The optional design field `preserveCanvas` defaults to false for old catalogs and is true for new designs and explicit editor saves. The native slot view uses fit for those saved composites so slightly different device-family proportions cannot introduce another crop of the exported canvas; any unused area retains transparency or the design's solid background. Older saved widgets retain their original fill behavior until saved again. The two new fields round-trip through existing private/shared schemas and publication without dropping assignments. Source-generated managed decoding remains strict; installing an older host after saving the new fields is unsupported and its decoder will reject them rather than silently discard edits.

Review also corrected a border-inset aspect mismatch: both guide strokes are reserved outside the actual photo canvas, keeping all four canvas proportions identical to export. This follows [MAUI 10.0.110 Border arrangement](https://github.com/dotnet/maui/blob/10.0.110/src/Controls/src/Core/Border/Border.cs), which insets content by its stroke thickness. Gesture positions are converted relative to the native canvas, while ghost/selection positions are relative to the workspace, so outer borders do not shift the overlay.

## Original editing behavior (0.2.22)

The editor uses a plain Light/Dark page with themed glass cards and the current app accent. Small, Medium, Large and iPhone XL segments change the preview proportions. The representative canvas sizes remain 170×170, 364×170, 364×382 and 364×594, scaled down only when the available width is smaller. WidgetKit controls actual Home Screen dimensions. XL requires iOS 27; retired iPad layouts still open as unsaved iPhone XL copies.

Tap a visible photo to select it. Drag moves its frame; pinch changes both dimensions around the gesture anchor; the four corner targets change width and height independently while holding the opposite corner. Native gestures temporarily suspend the ancestor scroll view, restore its previous state on completion/cancellation/disconnection, and restore the original layer if interrupted. Other editing actions are unavailable during manipulation. Geometry is bounded to the canvas with a minimum normalized width/height of .05. Tests caught and corrected floating-point subtraction at the minimum size that could otherwise reject a valid save.

The toolbar offers Reset, quarter-turn Rotate Left/Right, horizontal/vertical Flip, Opacity and confirmed Delete. Rotation turns the photo inside its cover-cropped frame. Reset centers an aspect-fitted frame within 80% of the canvas and restores rotation, flips, opacity, zoom and crop. It keeps the photo identity, name and visibility. Switching tools closes the previous tool panel. The opacity tool displays its current percentage.

Layer rows retain their thumbnail and native visibility switch across geometry updates. The list shows the topmost layer first. Drag the handle to reorder within this editor; the menu also provides Move forward/backward for accessible reordering, Rename, Size/position/crop and confirmed Delete. The precise panel retains independent dimensions, position, zoom and overflow-axis crop controls. Opening it scrolls it into view and respects Reduce Motion. Photo import still offers Photo Library and Files, enforces the existing eight-layer limit, and owns imported draft assets until saved or explicitly cleaned up.

Save renders and atomically persists the design through the existing repository, republishes assigned static slots, and marks the draft saved before attempting navigation. Cancel/navigation does not rewrite existing designs. Backgrounding cancels an active gesture and closes tool panels. Foreground checks reject late sheet actions; an already committed save can finish navigation after activation. Cleanup retains sources referenced by saved designs. Repeated live edits reuse image views instead of decoding each source for every gesture update.

### Rotate and Flip menu follow-up (0.2.23)

Rotate Left/Right and horizontal/vertical Flip now keep their menu open after applying an action, so repeated adjustments do not require reopening it. Tapping the active tool again closes it; choosing another tool or another layer also closes it. Gesture start, size changes, asynchronous actions, backgrounding and page departure retain their existing dismissal behavior. The change reuses the same draft transforms and Save/Cancel flow, with no persistence/schema or accessibility-control changes. Managed iOS C# compilation and the 148 app tests pass; repeated taps, VoiceOver focus and dismissal behavior still require an iPhone check. The owner authorized committing and pushing this follow-up to main, and subsequently authorized its inclusion in the 0.2.23 tag alongside the native transparency adapter.

## Transparency and compatibility

New designs start with no background fill on iOS 26+. Older systems start with a solid background. The reusable Settings/Clipboard colour picker supplies the optional solid colour. Existing designs without the new field keep their solid background. Switching modes retains the last valid solid colour.

The model adds optional `transparentBackground` (legacy default false), `quarterTurns` (0), `flipHorizontal`/`flipVertical` (false) and `opacity` (1). Existing private schema-1/schema-2 libraries and shared schema-1 catalogs still decode without rewriting on read. Reflection-disabled round-trip and repository tests cover the new values, slot retention, publication and rejected-edit preservation. Downgrading is unsupported: previous hosts reject these unknown fields through their strict decoder instead of silently discarding new edits. The Swift summary reads transparency as an optional Boolean for legacy catalogs.

UIKit exports both the full PNG and thumbnail with alpha when the design is transparent; the renderer clears rather than fills the canvas. Crop placement accounts for quarter turns, with matching native and MAUI rotation/flip/opacity transforms. The editor/gallery/slot checkerboard is a separate decorative view and is never part of either exported image. The native slot view uses a clear container for transparent designs and retains a system background for empty/error entries and legacy solid designs. Photos retain the existing full-colour accented rendering mode.

**Actual wallpaper-through transparency has not been verified in normal Home Screen styles.** The original 0.2.22 implementation uses public APIs to export alpha PNGs and request a clear WidgetKit container; these do not establish how the iOS compositor displays the widget. The owner's device test found a dark container in normal styles, becoming see-through in Clear style. Apple's [widget background documentation](https://developer.apple.com/documentation/widgetkit/displaying-the-right-widget-background) and [Liquid Glass guidance](https://developer.apple.com/documentation/WidgetKit/optimizing-your-widget-for-accented-rendering-mode-and-liquid-glass) describe system control over widget backgrounds. The [0.2.23 native transparency follow-up](widget-native-transparency.md) now adds a guarded private descriptor adapter for iOS 27. Its native build and device outcome still need verification. No wallpaper-screenshot workaround is implemented.
