Use `AccentButton` for native text-only primary actions and `AccentSurface` for primary surfaces with custom labels/icons. `ClipboardEditorActionButton`, `ProfileActionButton`, `ClipboardIconButton` and the Settings compact preview use these shared paths. Neutral cards, fields and secondary actions retain their own theme styling.

`AccentSurface` starts with a clean Border and binds **Background** directly to the solid `AccentButtonBrush`. It never inherits a card gradient, sets an accent through BackgroundColor, or supplies a manual fallback brush that would outrank the dynamic resource. Its read-only Foreground is calculated from the effective solid fill and caption size/weight. Bind each label/icon with `BindForeground`; foreground updates also follow brush colour mutations. Large bold captions use the existing 3:1 contrast rule; compact captions/icons use 4.5:1. The selected RGB stays unchanged in either theme.

Keep the transparent native hit target below the independently drawn, input-transparent surface. Press feedback may scale it; do not fade an entire primary action or place a gloss/material overlay over its caption, as that changes the background used for contrast. Disabled custom primary actions retain their full-opacity fill and caption; IsEnabled still blocks interaction.

The owner reported a dark Save item surface with black text in v0.2.8. The pinned MAUI 10.0.110 controls reproduce it: a themed Background gradient remains after RemoveBinding plus ClearValue, because ClearValue clears the manual setter value, not the binding's retained value. Setting BackgroundColor then leaves the gradient visible: MAUI's [effective Background implementation](https://github.com/dotnet/maui/blob/10.0.110/src/Controls/src/Core/VisualElement/VisualElement.cs) prefers a nonempty Background brush. New primary actions must start with AccentSurface rather than converting a themed card/field into a button.

When a control deliberately changes between a manual override and a dynamic resource on the same property, clear the manual value before returning to the resource. Clipboard headers do this when returning from a custom colour to the app accent. `ClipboardSegment` does it for its deselected transparent background/stroke before reselecting. Remove competing foreground theme bindings when changing palette owners.

`AccentControlTests` runs the actual production controls against the pinned MAUI Controls library on the plain net10.0 test target. It reproduces the released failure and checks effective paints and label/icon colours across presets/custom colours, Light/Dark switching, live resource changes, compact captions, pressed/disabled feedback, header recycling/reset and repeated selection. Headless dispatch is test-only. The packaging policy test requires primary accent resources to be owned by AccentButton/AccentSurface so new components cannot silently bind a primary colour on a themed card. Both existing CI workflows already run these tests; the IPA trigger remains new version tags only.

A native blank button remains underneath the independent visuals and becomes genuinely disabled; click dispatch also checks effective IsEnabled. The surface keeps full opacity and changes to an explicit neutral disabled fill, caption and outline. Enabled captions follow live AccentText, or the neutral caption binding for non-accent editor labels. Theme/accent palette sources have separate properties so repeated enabled/disabled switches never replace competing theme/resource bindings. Bind captions/icons using BindForeground rather than assigning their colours separately.

Disabled colours are `#515A6B` on `#E8ECF2` in Light mode and `#BCC4D2` on `#292D36` in Dark mode. Disabled outlines are `#7A8496` / `#7F8999`. Managed tests check at least 4.5:1 text contrast and 3:1 outline contrast against the fill, including theme changes while disabled. Do not lower a complete action's opacity to communicate availability. Use an explicit neutral palette and a reason, keep a minimum 44-point target, and clear any pressed scale when disabling. Filled primary actions continue to use AccentSurface and their existing contrast rules.

Clipboard and Arrange use a shared in-content PageActionBar to avoid UIKit's faint disabled toolbar title. It preserves the visible Back/title/Arrange/Add and Cancel/title/Done actions, with flexible single-line titles and automatically sized buttons; Clipboard's Back action pops the navigation stack. Secondary editor/profile buttons use the same disabled palette. The disabled custom-colour editor no longer adds a 40% parent-opacity fade. Icon-only card actions already draw their visuals separately and do not fade; primary surfaces retain their previous behaviour. Home/Widgets Refresh are not persistently disabled, and the native crop confirmation already supplies a disabled title colour. The intentionally paused Settings preview and brief press feedback are unrelated to availability.

## Row alignment audit (24 October 2026, unreleased)

The owner reported that the photo-layer visibility switch appeared raised. All four switch construction paths and fixed-size controls beside variable-height text were reviewed. [MAUI's alignment documentation](https://learn.microsoft.com/en-us/dotnet/maui/user-interface/align-position?view=net-maui-10.0) specifies `Fill` as the default and notes that it can override requested dimensions. The pinned [iOS Switch handler](https://github.com/dotnet/maui/blob/10.0.110/src/Core/src/Handlers/Switch/SwitchHandler.iOS.cs) always uses a container and preserves the native switch's natural size. The [iOS wrapper](https://github.com/dotnet/maui/blob/10.0.110/src/Core/src/Platform/iOS/WrapperView.cs) assigns its bounds to the native child during layout. These sources and the local row configuration identify a code-level alignment mismatch: the switch used `Fill` in a row whose height comes from its thumbnail/text, while adjacent text was centred. Exact UIKit pixel offsets have not been measured on the owner's phone.

Use `SettingsControls.RowSwitch` for switches beside row labels. It returns a standard MAUI Switch with vertical centring, end alignment and the existing dynamic Accent binding. It does not force native dimensions, apply transforms or add gesture handlers. All four existing switch sites now use this factory, including the already-centred Settings live-preview switch. Centre fixed-size tiles/buttons within taller rows; allow the surrounding row and text to grow normally. Full-size native hit-target overlays and intentionally top-aligned explanatory icons retain their layout behavior.
