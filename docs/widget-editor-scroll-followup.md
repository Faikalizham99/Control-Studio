# Layer-row and editor reflow follow-up — 0.2.36 (38)

The owner reported that tapping a layer's lock could move the editor towards the bottom, then authorized auditing and fixing related controls. Version 0.2.35 removed explicit MakeVisible calls and kept a minimum content extent. That prevented a shorter form from making the old offset unreachable, but did not preserve a row's screen position when a settings panel above it disappeared.

## Findings and changes

| Component | Cause or risk | Change |
| --- | --- | --- |
| Photo and clock Lock/Unlock | Both directions closed the selected layer's tools and precision area, then refreshed all rows. | Keep the selection and open tools. Update the affected row and selected controls only. Placement controls remain disabled while locked and become available again on unlock. |
| Layer Show/Hide | Refreshed every row and the selected controls, even when toggling another layer. Clock/blend notices can change height above Layers. | Retain native rows/switches, update only affected state, and anchor the visible row through necessary notice reflow. Unselected layer changes do not refresh the selected clock's panel. |
| Layer Options | Selected the target and closed tools before opening the menu. Generic async-operation setup and lifecycle callbacks also closed tools. | Opening/cancelling Options leaves selection and panels intact. Commands target the requested layer by ID. Lock, rename, crop, centre and reorder no longer require selecting it. Precision explicitly selects its target. Rename/delete cancellation leaves the previous selection intact. |
| Layer selection/outline | Switching layer kinds can close a tall panel above Layers. Selected borders changed from one to two points, potentially changing available row width near a wrapping threshold. | Capture the tapped row before selection; preserve its visible position through reflow. Reserve a two-point outline in both states; selection changes its colour only. |
| Photo/clock tools and font/weight choices | A stable numeric scroll offset alone does not account for controls moving inside a changing panel. Inline weight controls can disappear above the tapped font. | Capture the visible tapped tool/font/weight cell. After layout, compensate by its actual vertical movement. Horizontal strips remain manually scrolled. |
| Blend Done and precision Done | The button's own panel disappears. | If the next form section was already visible, use it as the fallback anchor. Hidden/detached anchors otherwise cancel cleanly. |
| Add-layer/photo/colour pickers, backgrounding and coverage | RunAsync, OnDisappearing and WindowDeactivated closed panels even on cancellation. | Keep panels/selection/highlights mounted; disable operations while busy. Suspend the canvas and blend sample resources while covered/inactive, reset pressed tool transforms, and resume on activation. No persisted editor UI state is added. |
| Widget background mode and status | Collapsing a solid-colour section or changing message height can reduce the form extent. | Preserve the current reachable viewport before changing visibility/text. |
| Clipboard Add/Edit header colour | Switching back to app accent collapses a colour section near the bottom of a ScrollView and can clamp its offset. | Reuse the editor viewport extent guard before the switch. Release its temporary minimum on actual departure. |

## Position preservation

`WidgetEditorForm` wraps the standard vertical layout manager and signals after children are arranged. `WidgetEditorScrollView` then dispatches a bounded correction against real positions: new anchor Y minus its captured screen Y. It sends an instant numeric `IScrollView.RequestScrollTo` only when movement is needed; it never requests MakeVisible or parks an element-scroll request. If the needed bottom extent has not been arranged yet, the existing minimum-height guard supplies it before correction. No fixed panel height, inserted gap between cards, timer or scroll-restoration loop is added.

The anchor is invalidated by manual/keyboard/accessibility scrolling, resizing, handler detachment, unloading, content replacement, backgrounding/coverage, departure, reordering or a newer captured action. Offscreen controls cannot trigger a reveal. The minimum extent still gives back temporary trailing space when scrolling towards the top. Real canvas size, exported geometry, saved layers and Home Screen rendering are unchanged.

The wider source audit included shared native icon/switch controls, Clipboard concealment, Settings/Profile, counter previews, widget gallery/slots/assignment and native reorder auto-scroll. Clipboard concealment already retains its measured layout. The other pages do not use the layer-refresh/panel-closing path; deliberate list filtering, keyboard/accessibility navigation, workspace centring and drag-edge scrolling are retained. This source review is not proof of device behaviour on every screen.
